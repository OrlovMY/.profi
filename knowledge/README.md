# knowledge/ — универсальные технические знания

Кросс-проектная база знаний. Не зависит от конкретного продукта.
Пополняется, когда команда изучила что-то новое и хочет применять это везде.

## Структура

| Папка | Что хранится | Пример |
|-------|-------------|--------|
| `standards/` | Минимальные планки качества — «не ниже этого» | Минимальный UI для любого проекта, минимум безопасности APK |
| `guides/` | Критерии выбора и подходы — «как правильно» | Выбор БД под условия, стратегия сборки APK, CI pipeline setup |
| `recipes/` | Конкретные команды и последовательности — «делай так» | Gradle release build, pg_dump restore, Docker multi-stage |

## Когда писать

- Изучили новый правильный способ делать что-то → `guides/`
- Договорились о минимальном стандарте для любого проекта → `standards/`
- Нашли рабочую последовательность команд, которую будем повторять → `recipes/`

## Что НЕ сюда

- Правила работы команды → `scenarios/` или `playbooks/`
- Роли агентов → `roles/`
- Специфика конкретного проекта → `memory/` того проекта

**Статус этого пункта — прямое указание владельца, 24.08.2026:** «Проектное всегда должно оставаться в проекте. Это тоже стоит явно прописать. В `.profi` может уходить только опыт, решения, выводы безотносительно проекта.» Практически: **датированный случай** из проекта в `.profi` уместен — это опыт (правило А2, `roles/big7/pe-01.md`); **действующее проектное указание** (какой ремоут, какие устройства, какой запрет сейчас действует) — нет: ему место в памяти проекта, а в `.profi` — общее правило и строка-указатель «действующие частности — в памяти проекта» (`rule-expiry-and-ownership.md`, п. 8).

## Формат файла

Формат ниже — для `guides/` и `recipes/`. Для `standards/` обязательны два поля в любом виде: когда правило действует и не действует («Применимость» / «Условия применения») и откуда оно («Источник»: дата, случай); остальное свободно. (24.08.2026: формату ниже следовали 0 из 43 стандартов и 5 из 7 guides/recipes — норма переписана под то, что исполняется, а не наоборот.)

Префикс заголовка («Standard:» / «Стандарт:» / без префикса) — свободный: принадлежность классу определяется каталогом `knowledge/standards/`, не заголовком; искать и считать стандарты — по каталогу, поиск по префиксу заголовка недосчитывает (25.08.2026: 31/4/12).

```markdown
# Тема

## Условия применения
Когда это актуально / для каких проектов.

## Суть
Что правильно и почему.

## Антипаттерны
Что делать не надо.

## Источник
Откуда знание (официальная дока, инцидент в проекте X, дата).
```
