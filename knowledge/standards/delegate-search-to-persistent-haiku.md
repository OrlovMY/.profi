# Standard: делегировать ПОИСК персистентному агенту механического яруса (retrieval ≠ суждение)

> Имя файла — исторический след (модель на дату заведения); действующий ярус — `scenarios/session-start.md`, Шаг 0.

**Статус:** обязательный · **Применимость:** ВСЕ проекты, любой момент, когда нужен поиск в коде/истории/доке/памяти.
**Происхождение:** предложение владельца 2026-07-07 («на поиск чего-то в коде или истории отдельный постоянный, не выключаемый, Haiku-агент») → вердикт Большой 7 (APPROVE) той же датой.

## Правило (load-bearing принцип)

**Разделяющая линия: RETRIEVAL/факты (механический ярус) vs СУЖДЕНИЕ/синтез (решающий ярус: координатор/ядро).**
Поиск (grep/glob/git-log/history/doc-lookup) — механический, делегируемый, дешёвый. Отдавать его **одному персистентному поисковому агенту механического яруса**. Он возвращает **КАНДИДАТЫ + ФАКТЫ** (file:line, commit-hash, дата, grep-hits, «X определён в Y», «менялся Z»); координатор/Big-7 **СУДИТ**, что это значит. Этот принцип разрешает и scope, и границы.

Зачем: освобождает координатор (решающий ярус) и держит его контекст чистым (получаю ВЫВОД/локацию, не дампы файлов); дешевле (механический ярус ≪ решающего и кодового); параллелизм; персистентность копит familiarity кодовой базы.

## 1. Доверить (чистый retrieval) ✅
- where-defined / where-used; when-changed (git-log/blame); find-file; grep-pattern; does-Z-exist; локация symbol/endpoint/строки.
- read-and-summarize — для **структурного/фактического** summary («какие функции/структура в файле», «файл содержит X/Y/Z»), НЕ оценочного.
- doc/passport-lookup — «что док ГОВОРИТ про X» + локация (retrieval), НЕ «правда ли это».
- memory-recall — «что память ГОВОРИТ» (retrieval).
- fact-extraction — ФАКТЫ (даты/коммиты/значения), НЕ причинность/интерпретация.

Возврат: локации/рефы/факты/quote, **НЕ дампы**.

## 2. НЕ доверять (суждение/синтез) ⛔
Анализ/аудит (Big-7), написание кода (кодовый ярус), решения/дизайн, **judgment-laden выводы.**

🎯 **Канонический пример (в стандарт дословно) — SMS-хант:** на вопрос «подтвердил ли owner, что SMS работает» поисковый агент НАХОДИТ строку «РАБОТАЕТ» (retrieval ✅), но НЕ ДОЛЖЕН заключить «SMS работает» — это было недоказанное предположение, отличить doc-утверждение от реального подтверждения требует СУЖДЕНИЯ. Правило: **поисковый агент СОБИРАЕТ кандидаты/факты; решающий ярус СУДИТ. Для критичных/нюансных выводов вердикт поискового агента не доверять — только сбор.**

## 3. Обязательные оговорки (лечат ровно SMS-precedent-провал)
- 🔴 **Retrieval С ОКРУЖАЮЩИМ КОНТЕКСТОМ, не обрезанный-до-хита.** Поисковый агент возвращает хит + соседние caveats/qualifiers/даты. В SMS-случае у «РАБОТАЕТ» рядом был caveat («причинность не доказана, откатывается на ребуте»); хит без caveat = судья голодает. **Retrieval, скрывающий caveat, = суждение-под-видом-retrieval** — запрещён.
- 🔴 **no-guessing сохранён:** поисковый агент репортит «нет хитов для [точный pattern/scope]» (bounded), НЕ «X не существует» (unbounded). «Не нашёл» ≠ «нет» — исчерпывающесть поиска решает судья. Факты/локации, никогда догадки.
- 🔴 **Output не exfil'ит секреты (SEC-02):** для secret-bearing хита возвращать **file:line, НЕ значение секрета**. Грепнул файл с токеном → отдаёт локацию, не токен (совпадает с «локации не дампы» + no-token-logging).

## 4. Механика
- **Один персистентный поисковый агент** (не плодить), SendMessage-реюз (копит контекст кодовой базы).
- Tools: **read-only** (Grep/Glob/Read/Bash-read-only-git). НЕТ write/destructive/prod/commit.
- Модель — механический ярус (`scenarios/session-start.md`, Шаг 0). Держать фоном.
- ⚠️ **Персистентность = УДОБСТВО, не эссенция (в отличие от Big-7).** Retrieval почти stateless — свежий поисковый агент грепнет так же. → держать персистентным ради familiarity, но **свободно ресетить без потери**, если контекст пухнет. Не over-инвестировать в его persistence (Big-7 персистентность эссенциальна — continuity суждения; поисковый — нет).

## 5. Иерархия делегирования (консистентна)
**Механический ярус = retrieval → кодовый = implementation → решающий: координатор = coordination/judgment → ядро = audit/decision.**
Принцип: **делегируй ВНИЗ дешевейшей модели, способной сделать задачу БЕЗ суждения; суждение/решение/аудит остаётся на решающем ярусе.** И поисковый (retrieval), и кодовый (код) возвращают РАБОТУ на judgment/audit решающего яруса — когерентный паттерн (дешёвые ДЕЛАЮТ, решающий ярус СУДИТ/аудирует). Расширяет `delegate-implementation-to-sonnet` добавлением механического яруса (retrieval) ниже.

## SEC-02 / profi-content-security-gate
Сам стандарт универсален, без проектных секретов (проходит 3 теста). Поисковый агент в приватном коде = тот же trust, что остальные ярусы (нет новой экспозиции). Output-не-exfil-секретов (§3) — обязательное условие.

## ⚠️ Пропагация — фиксировать в КАЖДОМ проекте
Универсальный стандарт, источник истины здесь (`.profi`). **В памяти каждого проекта — строка-указатель** (одна строка в `MEMORY.md` с `[[...]]`), как для `delegate-implementation-to-sonnet`. При старте в новом проекте: нет записи → добавить в тот же ход.
