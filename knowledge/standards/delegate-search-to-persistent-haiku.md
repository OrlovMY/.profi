# Standard: делегировать ПОИСК персистентному Haiku-агенту (retrieval ≠ суждение)

**Статус:** обязательный · **Применимость:** ВСЕ проекты, любой момент, когда нужен поиск в коде/истории/доке/памяти.
**Происхождение:** предложение владельца 2026-07-07 («на поиск чего-то в коде или истории отдельный постоянный, не выключаемый, Haiku-агент») → вердикт Большой 7 (APPROVE) той же датой.

## Правило (load-bearing принцип)

**Разделяющая линия: RETRIEVAL/факты (Haiku) vs СУЖДЕНИЕ/синтез (Opus/Big-7).**
Поиск (grep/glob/git-log/history/doc-lookup) — механический, делегируемый, дешёвый. Отдавать его **одному персистентному Haiku-агенту**. Haiku возвращает **КАНДИДАТЫ + ФАКТЫ** (file:line, commit-hash, дата, grep-hits, «X определён в Y», «менялся Z»); координатор/Big-7 **СУДИТ**, что это значит. Этот принцип разрешает и scope, и границы.

Зачем: освобождает координатор (Opus) и держит его контекст чистым (получаю ВЫВОД/локацию, не дампы файлов); дешевле (Haiku ≪ Opus/Sonnet); параллелизм; персистентность копит familiarity кодовой базы.

## 1. Доверить (чистый retrieval) ✅
- where-defined / where-used; when-changed (git-log/blame); find-file; grep-pattern; does-Z-exist; локация symbol/endpoint/строки.
- read-and-summarize — для **структурного/фактического** summary («какие функции/структура в файле», «файл содержит X/Y/Z»), НЕ оценочного.
- doc/passport-lookup — «что док ГОВОРИТ про X» + локация (retrieval), НЕ «правда ли это».
- memory-recall — «что память ГОВОРИТ» (retrieval).
- fact-extraction — ФАКТЫ (даты/коммиты/значения), НЕ причинность/интерпретация.

Возврат: локации/рефы/факты/quote, **НЕ дампы**.

## 2. НЕ доверять (суждение/синтез) ⛔
Анализ/аудит (Big-7), написание кода (Sonnet), решения/дизайн, **judgment-laden выводы.**

🎯 **Канонический пример (в стандарт дословно) — SMS-хант:** на вопрос «подтвердил ли owner, что SMS работает» Haiku НАХОДИТ строку «РАБОТАЕТ» (retrieval ✅), но НЕ ДОЛЖЕН заключить «SMS работает» — это было недоказанное предположение, отличить doc-утверждение от реального подтверждения требует СУЖДЕНИЯ. Правило: **Haiku СОБИРАЕТ кандидаты/факты; Opus/Big-7 СУДИТ. Для критичных/нюансных выводов вердикт Haiku не доверять — только сбор.**

## 3. Обязательные оговорки (лечат ровно SMS-precedent-провал)
- 🔴 **Retrieval С ОКРУЖАЮЩИМ КОНТЕКСТОМ, не обрезанный-до-хита.** Haiku возвращает хит + соседние caveats/qualifiers/даты. В SMS-случае у «РАБОТАЕТ» рядом был caveat («причинность не доказана, откатывается на ребуте»); хит без caveat = судья голодает. **Retrieval, скрывающий caveat, = суждение-под-видом-retrieval** — запрещён.
- 🔴 **no-guessing сохранён:** Haiku репортит «нет хитов для [точный pattern/scope]» (bounded), НЕ «X не существует» (unbounded). «Не нашёл» ≠ «нет» — исчерпывающесть поиска решает судья. Факты/локации, никогда догадки.
- 🔴 **Output не exfil'ит секреты (SEC-02):** для secret-bearing хита возвращать **file:line, НЕ значение секрета**. Грепнул файл с токеном → отдаёт локацию, не токен (совпадает с «локации не дампы» + no-token-logging).

## 4. Механика
- **Один персистентный Haiku-агент** (не плодить), SendMessage-реюз (копит контекст кодовой базы).
- Tools: **read-only** (Grep/Glob/Read/Bash-read-only-git). НЕТ write/destructive/prod/commit.
- model = haiku. Держать фоном.
- ⚠️ **Персистентность = УДОБСТВО, не эссенция (в отличие от Big-7).** Retrieval почти stateless — свежий Haiku грепнет так же. → держать персистентным ради familiarity, но **свободно ресетить без потери**, если контекст пухнет. Не over-инвестировать в его persistence (Big-7 персистентность эссенциальна — continuity суждения; Haiku — нет).

## 5. Иерархия делегирования (консистентна)
**Haiku = retrieval → Sonnet = implementation → Opus = coordination/judgment → Big-7 = audit/decision.**
Принцип: **делегируй ВНИЗ дешевейшей модели, способной сделать задачу БЕЗ суждения; суждение/решение/аудит остаётся на Opus/Big-7.** И Haiku (retrieval), и Sonnet (код) возвращают РАБОТУ на judgment/audit Opus/Big-7 — когерентный паттерн (дешёвые ДЕЛАЮТ, Opus/Big-7 СУДЯТ/аудируют). Расширяет `delegate-implementation-to-sonnet` добавлением Haiku=retrieval ниже.

## SEC-02 / profi-content-security-gate
Сам стандарт универсален, без проектных секретов (проходит 3 теста). Haiku в приватном коде = тот же trust, что Opus/Sonnet (нет новой экспозиции). Output-не-exfil-секретов (§3) — обязательное условие.

## ⚠️ Пропагация — фиксировать в КАЖДОМ проекте
Универсальный стандарт, источник истины здесь (`.profi`). **В памяти каждого проекта — строка-указатель** (одна строка в `MEMORY.md` с `[[...]]`), как для `delegate-implementation-to-sonnet`. При старте в новом проекте: нет записи → добавить в тот же ход.
