# Standard: DR-зеркало git — синхронно в оба remote

**Статус:** обязательный · **Применимость:** любой проект с зеркалом репозитория (disaster recovery).

## Правило
Если у репозитория есть DR-зеркало (второй remote: GitHub↔GitLab и т.п.) — после **каждого** push в основной remote немедленно пушить и в зеркало. «Потом» = окно рассинхрона = потеря при сбое основного хоста.

```
git push <адрес записи> <branch> && git push <зеркало> <branch>
```

- Конкретные remote-URL и имена зеркал — в памяти/доке проекта, НЕ в этом универсальном правиле. **Имя ремоута — псевдоним, а не адрес:** в MDMy `origin` за одни сутки 19.08.2026 сменил назначение с GitLab на GitHub. Поэтому правило называет роли («адрес записи», «зеркало»), а не имена.
- Держать одинаковый набор веток (или явно знать, что зеркалится только основная).

## Приостановка или прекращение зеркалирования — как выглядит

Зеркалирование может быть **приостановлено или прекращено владельцем** — тогда push в зеркало пропускается, и правило не нарушено. Решение обязано быть **записано в памяти проекта** с датой и признаком: приостановка — с условием снятия, прекращение — с новым статусом бывшего зеркала (обычно «только чтение/архив»). Действующие решения в тексте этого стандарта не живут (проектное — в проекте, `knowledge/README.md`); здесь — только форма:

```bash
git push <адрес-записи> <branch>
# git push <зеркало> <branch>   # ⏳ приостановлено владельцем <дата>, условие снятия — в памяти проекта;
#                               #    имя зеркала — из git remote -v, не из памяти
```

Приостановленную строку держать закомментированной с меткой `⏳`, датой и адресом записи: удаление потеряет то, что придётся возвращать. **Прекращённое** зеркалирование (владелец решил насовсем) — строку удалить вместе с меткой, оставив в памяти проекта запись «зеркало X прекращено <дата>, статус — только чтение/архив»: закомментированная строка без условия снятия — постоянная оговорка (`git-branch-discipline.md`, выноска «Непустой вывод…»: оговорка без даты снятия — постоянная).

(Переходно: в MDMy на 24.08.2026 действует — писать только в GitHub, GitLab — только чтение/архив; решение владельца 18.08 + 24.08. Скобка снимается ходом, которым запись подтверждена в памяти проекта.)

**Насколько разошлось зеркало — измерять, а не предполагать, и измерять после `fetch`:** `git fetch <зеркало> && git rev-list --count <зеркало>/master..master`. Ноль означает, что зеркало догнало. Без `fetch` число говорит о свежести локального ref, а не о состоянии зеркала — 19.08.2026 эти две неисправности дали одинаковый симптом и были разведены только свежим чтением. Конкретную величину здесь не фиксируем: она меняется ежедневно, а правило — нет.

Случай, из которого раздел вырос: в проекте-источнике (MDMy) 18.08.2026 владелец приостановил запись в зеркало, 24.08.2026 сделал решение **постоянным** (бывшее зеркало — только чтение/архив). Действующая запись — в памяти того проекта.

## Зачем
DR-зеркало имеет смысл только синхронным. Рассинхронизированное зеркало создаёт ложное чувство защищённости.
